# ADR-0026：加入「今天想去哪一類」，用選項不用 AI

- **狀態**：已採納（設計定案，尚未實作）
- **日期**：2026-09-02
- **相關**：設計架構書 v1.0 §8、§6.3、§7.4、憲法「AI 的使用判準」
- **偏離**：§8「可覆寫的範圍限於：家長負擔上限、可用時間窗、車程上限、是否避開人多、放電強度上限」——**加入第六項**

## 背景

使用者列出他實際的四個決策考量：

1. 小孩適不適合這個年紀 → `suitableAgeMonths`、`facilityAgeBands` ✅
2. 夠不夠空曠、熱不熱 → `runnableSpace`、`shadeLevel`、`hasAirConditioning` ✅
3. 太遠嗎、午睡來不來得及 → 時間軸與午睡衝突 ✅（見 ADR-0025）
4. **大人自己喜不喜歡**——「有時候想去海邊，有時候想去美術館，
   有時候想去親子館」 → **模型裡沒有任何對應**

模型裡跟喜好有關的只有三種，沒有一種是第 4 點：

| 既有 | 性質 |
|---|---|
| `familyPreferences.outdoorTendency` | 常態 |
| `categoryPreferences.learnedWeight` | 學來的常態 |
| `contextOverrides`（§8） | 一次性，但**五項不含類別** |

**系統把偏好都當成慢變數，但「大人今天想幹嘛」是快變數**，而且使用者
明確指出那是實際會影響決定的因素。

## 使用者提的形式

> 有沒有可能是在一開始問說今天想去哪：「室內（美術館／圖書館）」
> 「郊外（海邊／公園）」「沒想法你推薦吧」，再依照大人今天喜好去推薦？

## 為什麼選項式比 §8 的自由輸入更好

§8 的一次性情境是「自由輸入框 + AI 轉譯」。而這件事**根本不需要 AI**：

| | §8 現有 | 本 ADR |
|---|---|---|
| 形式 | 自由文字 → AI 轉譯 | 四個按鈕 |
| 需要 AI | 是 | **否** |
| 可測試 | 難（轉譯不可重現） | 是（就是四個值） |
| 離線可用（P9） | 否 | **是** |

憲法規定 AI 只能「轉譯輸入」不能「決定排序」。而「想待在有冷氣的地方」
不需要轉譯——**它本身就是那個值**。少一層 AI 就少一個不可重現的環節。

## 選項的切法

不用「室內／戶外」兩分，因為使用者自己的例子就穿過那條線——親子館是
室內，但跟美術館的體感完全不同。改用**體感群組**：

| 選項 | 對應類別 |
|---|---|
| 想待在有冷氣的地方 | 圖書館、博物館／美術館、親子館 |
| 想讓他跑一跑 | 一般公園、共融／特色遊戲場、室內遊樂場 |
| 想去遠一點的 | 海邊、農場、觀光景點 |
| **沒想法，你推薦吧** | 不套用（預設） |

第三項有個附帶效果：它其實同時在說「今天願意多開一點車」，
而車程上限**本來就在 §8 允許覆寫的五項裡**。

## 兩個機制上的決定

### 一、強力加分，不是硬過濾

硬過濾的失敗模式很糟：雨天選「想讓他跑一跑」→ 戶外選項已被 rain 剔除
→ 兩個條件相乘後**存活數為零** → 推播說「今天不要出門」。
但使用者其實很樂意去親子館，只是他早上按了那個鍵。

**明確意圖不該把系統逼進死路。** 加分保留了安全網：想跑的地方會排前面，
但真的都不能去時，系統仍然給得出室內選項。

這也符合憲法「偏好只能調整排序，永遠不能覆蓋硬過濾」。

### 二、不受 §7.4 的偏好抑制影響

§7.4 在受限情境（降雨 ≥40%、體感 ≥32°C、存活 <5）把家庭偏好權重歸零。
理由是**學習來的**偏好會壓死室內選項，而雨天正是最需要它們的時候。

但當日意圖不是學來的，是**人在看得到今天天氣的情況下自己按的**。
把它一起歸零，等於系統對使用者說「我知道你剛才選了什麼，但我不理你」——
而使用者不會知道發生了什麼事。

所以當日意圖是**獨立於 `familyPreference` 的加分項**，不受抑制。
它仍然過不了硬過濾，安全性由那一層保證。

> 這一條是本 ADR 最容易被日後「優化」掉的地方。抑制機制存在的理由是
> 對付**慢變數**；把快變數也一起關掉是誤用。

## 決定

1. `ContextOverrideValues` 加入第六項 `dayIntent`
2. 值為四選一，其中「沒想法」等同不設定
3. 進入評分而非硬過濾，且不受 §7.4 抑制
4. **僅對本次有效**，不寫入 `familyPreferences` 也不影響
   `categoryPreferences` 的學習（§8.3 既有規定）
5. 依 §8.4，套用過的當日意圖須連同該次造訪紀錄保存——
   否則日後會把「因為那天想去海邊才去沙灘」誤讀成長期偏好

## 尚未決定

- **問在哪裡。** 使用者說「一開始問」，但 §9.1 的推播必須自成完整答案、
  不得要求開啟 App。所以推播仍然要在沒有意圖的情況下給出建議，
  而落地頁才提供這個選擇。兩者的關係要在做推播時一起想。
- **加分的幅度。** 屬於 `weights.ts`，而 CONTRIBUTING 規定 tune 必須寫出
  觸發調整的實際觀察。目前一次觀察都還沒有，先實作再校準。

## 後果

- §8 的五項變六項。設計架構書該補一句，或由本 ADR 明文推翻（依 AGENTS.md
  的例外條款，個別決定可被 ADR 推翻）
- 「海邊、農場、觀光景點」這些類別目前**資料庫裡一個都沒有**
  （見 ADR-0024 的查證）。所以第三個選項短期內會沒東西可推——
  這不是實作問題，是覆蓋率問題，覆蓋率診斷會繼續指出它
