# ADR-0025：停留時長由小孩的專注度封頂

- **狀態**：已採納
- **日期**：2026-09-02
- **相關**：設計架構書 v1.0 §6.1、§7.1、§7.5
- **缺口**：§6.1 的小孩語彙表沒有「能專注多久」

## 背景

使用者舉了兩個他實際跑過的行程，時間結構完全相同：

```
8:00 出門 → 9:00 抵達（和平島親子泳池／基隆親子館）
→ 玩約 1 小時 → 10:30 回程 → 12:00 到家睡午覺
```

而他對停留時間的描述是：

> 好玩或有時間就多待，沒時間就早點走。
> **我自己在決策過程，好像從沒想過這個地點適合待多久。**
>
> 目前的年紀 1 個小時左右大概是專注度的上限。

## 問題

`typicalDurationMinutes` 是**地點**的欄位（遊戲場先驗 90 分、圖書館 60 分）。
但使用者去和平島玩一小時、去親子館也玩一小時——**同樣的一小時，因為那是
小孩撐得住的長度，不是地點的性質**。

而 §6.1 的小孩語彙表只有 napStage、wakeTime、napWindows、bedTime、mobility，
**沒有任何欄位記錄專注時長**。這是第五個同型的規格缺口：
§6 定義了概念但沒有欄位能回答它。

## 為什麼這個數字重要

停留時長同時進入兩個地方：

1. **硬過濾的「時間夠不夠來回」**（filters.ts）
2. **時間軸的「幾點到家」**（timeline.ts）——而那正是午睡衝突的依據

用使用者的真實行程算：單程 60 分、停留 60 分、回程 60 分 = **180 分**。
若照遊戲場的先驗 90 分算則是 **210 分**——時間窗剩 200 分時就會被
`not_enough_time` 剔除，而那是一趟他**實際做得到而且做過**的行程。

**高估停留時間會讓遠一點但可行的地方消失，而那正是使用者會去的那種。**

## 決定

`children` 加一個**選填**欄位 `attentionSpanMinutes`。

停留時長取兩者的較小值：

```
實際停留 = min(地點的先驗時長, 小孩的專注度)
```

三項細節：

1. **選填，留空＝不設限。** 不填就完全沿用現有行為，一個測試守著這條。
2. **多小孩取最短的那一個。** 與 §7.2「取最低分而非平均」同一個保守
   原則——**你是在最小的那個崩潰時離開的**，不是在平均值離開。
3. **地點先驗仍是上限。** 有些地方待太短沒意義（導覽制的農場），
   所以取 min 而不是直接用專注度取代。

驗證範圍 5–480 分：填 1 分鐘會讓每個地點的停留時間都變成 1 分鐘，
而**那不會有任何錯誤訊息，只會讓推薦悄悄失真**。

## 沒有做的事

使用者同時提出一個更根本的問題：**停留時間是不是根本不該是地點的屬性？**

那個方向（改成完全推導：`min(專注度, 剩餘時間)`）更貼近真實行為，
但會改動資料模型與時間軸的語意，且會失去「這裡待太短沒意義」這個資訊。
本 ADR 只做封頂，不重新定義 `typicalDurationMinutes`。

同一輪討論還浮出「**今天大人想去哪一類**」完全沒有容身之處——
`outdoorTendency` 是常態、`categoryPreferences` 是學來的常態，
而 §8 允許覆寫的五項不包含類別偏好。那是獨立的一則決定。

## 後果

- 使用者不填時行為不變，所以這個改動對現有資料是安全的
- 填了之後，遠一點的地點會開始通過硬過濾——這是刻意的
- 專注度會隨年齡改變，與 napStage 同屬慢變數，需要偶爾回頭調整
