# ADR-0014：資料模型的五項取捨定案

- **狀態**：已採納
- **日期**：2026-08-25
- **相關**：[`docs/資料模型草案.md`](../資料模型草案.md)、設計架構書 v1.0 §6、§7.1
- **修正**：[ADR-0013](0013-geometric-baseline-drive-estimate.md) 關於「誤差刻意偏向低估」的指引

## 背景

資料模型草案列出五個待確認事項，使用者於 2026-08-25 逐項確認。
本文記錄結論與理由，schema 依此撰寫。

---

## 一、`suitableAgeMonths` 與 `facilityAgeBands` 兩者都保留

§7.1 的過濾表列了兩條不同規則（「月齡不在適用年齡範圍內」與
「有遊具設施但不含小孩年齡層」），但 §6.2 的語彙表只定義了後者。

**兩者都需要**：步道沒有遊具設施（`facilityAgeBands = null`），
但它對六個月大的嬰兒仍然不適合——那要靠 `suitableAgeMonths` 擋。
兩者回答的是不同的問題：

- `suitableAgeMonths`：**這個地方**適合幾歲的小孩
- `facilityAgeBands`：**現場的遊具**適合幾歲的小孩（沒有遊具則為 null）

`suitableAgeMonths` 由類別先驗給預設值。**§6.2 的語彙表應視為缺漏，
而非「不需要這個概念」。**

## 二、`usesFreeway` 用直線距離啟發式判斷

ADR-0013 之後匯入階段不呼叫 Google，拿不到路線資訊，
但 §11.2 靠它決定連假係數、§10.3.2 靠它跳過即時查詢。

**做法**：超過一個距離門檻就視為走國道。門檻是領域參數，集中管理。

### 順帶修正 ADR-0013 的一個過度指引

ADR-0013 寫了「誤差要刻意偏向低估」。撰寫草案時發現這與 `usesFreeway`
的保守判斷方向相反，進一步檢視後認為**「刻意低估」這個指引本身就是多餘的**。

§7.1 已經把緩衝放在門檻上：「門檻放寬約 20%，避免粗估誤差誤殺」。
在估計值裡再加一層偏移，等於引入第二層、而且無法單獨調整的緩衝。

而且放行過多**不是免費的**：Stage 2 只挑前 8 名去精算，
一個被低估的遠地點會擠掉一個真正到得了的近地點。
ADR-0013 原本的論證（低估的代價只是多一次精算）忽略了這個排擠效應。

**修正後的分工：**

| 環節 | 原則 |
|------|------|
| 幾何車程估計 | **求準**，不刻意偏移 |
| `usesFreeway` 判斷 | **求準**，不刻意偏移 |
| 粗篩門檻 | 放寬 20%——**唯一的緩衝，而且是一個可調的數字** |

這符合 §13.2.10「門檻值、權重、係數集中管理」：
誤差容忍度應該是一個看得到、調得動的參數，不是散在兩處的隱性偏移。

ADR-0013 的其餘部分（不呼叫 Google、不儲存車程、合規理由）**完全有效**。

## 三、`durationFeeling` 的修正規則

- **至少 3 筆同方向**才調整 `typicalDurationMinutes`
- 每次調整 **±15%**
- **只調整 `fieldSources` 仍為 `category_prior` 的值**

第三條是關鍵：使用者手動設過的時長不該被自動覆蓋。
這與匯入器的 upsert 規則是同一個原則——**人確認過的東西，系統不動。**

三筆的門檻是為了避免單次異常（那天小孩剛好沒睡飽）就改動建檔值。

## 四、Visit 保存當日天氣快照

v1.0 §6.4 沒提，v0.2 有。**保留。**

理由：它是系統填的、零使用者負擔，而且**事後補不回來**——
兩年後想知道「那天下小雨結果還是很順利」，沒有快照就永遠查不到。

這與 §13.2.6「除兩項回饋外皆為選填」不衝突：那條規範的是使用者的填寫負擔，
不是系統能記錄的範圍。

## 五、`outdoorTendency` 用 −2…+2 五段

而非 0–100 連續值。

理由：初始三題要好回答，而 §6.3 硬性要求 UI 顯示學習結果與依據
（「戶外公園 +35%，依你最近 12 次選擇」）——**五段的離散值講得清楚，
連續值講不清楚。**

---

## 後果

- 資料模型草案的五個 ❓ 全部解除，可據以撰寫 schema
- ADR-0013 的「刻意低估」指引作廢，改為「求準 + 門檻放寬 20%」
- 新增領域參數：年齡層對應月齡、國道判定距離門檻、時長修正幅度與筆數門檻

### 什麼情況下該重新考慮

1. 若實際使用發現粗篩放行的地點遠多於 8 個且品質參差，
   代表門檻的 20% 太寬或幾何估計偏差過大——**先調那個參數，不要動估計公式**
2. 若 `usesFreeway` 的距離門檻在實際使用中頻繁誤判（例如把市區長距離判成國道），
   再考慮改用其他訊號（例如由精算結果回填，但需先確認 ToS）
